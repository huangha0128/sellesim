YYeSim 开放平台 API

面向分销伙伴 / 个人主体的 REST API。接入方以 keyId + keySecret 调用，可自助查价、下单、支付、退款、接收回调，数据按主体隔离。

基地址 https://<你的域名>/api/open/v1。 凭证由平台管理员在后台开通并发放，接入方无法自助注册。本文档为公开说明，实际调用需持有有效密钥。

一、鉴权与签名

采用双模鉴权：读接口（GET）只需 X-Api-Key；写接口（POST）需在 X-Api-Key 之外额外携带 X-Timestamp、X-Nonce、X-Sign 签名，防止密钥泄露后被用于下单/退款。

请求头必填说明
X-Api-Key读+写公开密钥 ID，如 ak_live_7f3a9c21（由后台发放）
X-Timestamp写毫秒时间戳，服务端校验与当前时间差在 ±5 分钟内
X-Nonce写随机串（建议 16 字节 hex），5 分钟内同一值不可重复（防重放）
X-Sign写签名，见下方算法

签名算法

X-Sign = hex(HMAC-SHA256(keySecret, content))
content = keyId + "\n" + timestamp + "\n" + nonce + "\n" + rawBody
  • rawBody 为请求体的原始字节（JSON 原文，不得重新序列化）；GET 等无请求体时为空串。
  • 示例（Node.js）：crypto.createHmac('sha256', keySecret).update(keyId+"\n"+timestamp+"\n"+nonce+"\n"+rawBody).digest('hex')

二、响应结构

所有接口统一返回 HTTP 状态码 + JSON 信封：

{
  "code": 0,                          // 0 成功；非 0 为业务错误码（见下表）
  "message": "ok",
  "data": { },                       // 业务数据，失败时为 null/无
  "requestId": "req_1a2b3c4d"    // 请求追踪号，排查问题时提供
}

三、错误码

code / HTTP含义
400参数错误（缺少/格式不正确）
401未鉴权：缺少 X-Api-Key、密钥无效/停用/过期、签名校验失败、时间戳越界、nonce 重放
403IP 不在该密钥的白名单内
404资源不存在（套餐/订单/退款单/主体不可见）
429请求过于频繁（触发限流）
500服务内部错误，请稍后重试
502上游套餐源（Tiger）异常或未配置

四、读接口（仅需 X-Api-Key）

GET/me鉴权 X-Api-Key

获取当前主体信息与本次使用的密钥信息。

无参数
{
  "subject": { "id":"...", "name":"分销A", "status":"active", "callbackUrl": "https://...", "defaultMarkupPercent": null },
  "key": { "keyId": "ak_live_...", "mode": "live" }
}
GET/packages鉴权 X-Api-Key

分页查询套餐列表。价格已按当前主体的定价解析（含加价/独立价/不可见过滤）。

countryCodekeywordpagepageSize
Query 参数说明
countryCode可选，按国家代码过滤
keyword可选，名称/地区模糊搜索
page可选，页码，默认 1
pageSize可选，每页条数，默认 20，最大 100
// data.packages[] 每项（节选）
{ "id":"...", "name":"日本 7天 5GB", "countryCode":"JP", "gb":5, "days":7, "price":39.9 }
"total": 12, "page": 1, "pageSize": 20
GET/packages/:pkgId鉴权 X-Api-Key

查询单个套餐详情（含主体售价）。主体不可见的套餐返回 404。

"data": { "pkg": { "id":"...", "name":"...", "gb":5, "days":7, "price":39.9, "features": [...], "installSteps": [...] } }
GET/regions鉴权 X-Api-Key

可用国家/地区列表（仅主体可见套餐覆盖的地区），按优先级/热度排序。

"data": { "regions": [ { "code":"JP", "name":"日本", "en":"Japan", "flag":"https://...", "hot":10, "priority":1 } ] }
GET/orders鉴权 X-Api-Key

分页查询本主体的订单列表（含退款相关字段，不含 eSIM 敏感信息）。

statusextOrderNopagepageSize
"data": { "orders": [ { "orderNo":"DPH...", "status":"paid", "pkgName":"...", "price":39.9, "extOrderNo":"...", ... } ], "total":5, "page":1, "pageSize":20 }
status含义
pending待支付
paid已支付
refunded已退款
GET/orders/:orderNo鉴权 X-Api-Key

订单详情。订单已支付（paid）时返回激活码 / ICCID / SMDP 等敏感信息；待支付一律省略。

"data": { "order": {
  "orderNo":"DPH...", "status":"paid", "extOrderNo":null, "price":39.9,
  "esim": { "status":"active", "used":120, "activatedAt":"...", "expireAt":"...",
             "activationCode":"LPA:1$tiger...", "iccid":"89...", "smdp":"smdp..." }
} }
GET/orders/ext/:extOrderNo鉴权 X-Api-Key

按接入方自定义订单号（extOrderNo）反查订单，返回结构同「订单详情」。

GET/orders/:orderNo/esim鉴权 X-Api-Key

查询订单对应 eSIM 的用量与状态（ICCID、套餐、用量等）。

"data": { "esim": { "iccid":"89...", "status":"active", "gb":5, "days":7, "used":120, "isUnlimited":false } }
GET/refunds/:refundNo鉴权 X-Api-Key

查询退款单详情。

"data": { "refund": { "refundNo":"RF...", "orderNo":"DPH...", "amount":39.9, "status":"refunded", "reason":"...", "createdAt":"..." } }

五、写接口（需 X-Api-Key + 签名）

写接口除 X-Api-Key 外必须携带 X-Timestamp / X-Nonce / X-Sign，签名算法见上文。
POST/orders鉴权 Key + 签名

创建订单并返回 H5 支付链接。同一 extOrderNo 重复提交时幂等返回已有订单。

请求体

{ "pkgId": "xxx",                        // 必填，套餐 ID（见 /packages）
  "email": "user@example.com",          // 必填，激活码将发送至此邮箱
  "extOrderNo": "MY-ORDER-001",         // 可选，接入方订单号，用于对账/反查/幂等
  "returnUrl": "https://..." }          // 可选，支付完成回跳地址（http/https）
"data": { "orderNo":"DPH...", "extOrderNo":"MY-ORDER-001",
  "payUrl":"https://...", "price":39.9, "totalAmount":39.9, "paid":false }
POST/orders/:orderNo/refunds鉴权 Key + 签名

主体自助退款（仅未激活的已支付订单可退，无需后台审批）。成功后退款金额原路返回支付宝，订单置为已退款并释放卡片。

extRefundNo 可选amount 可选reason 可选
{ "extRefundNo": "RF-001",    // 可选，接入方退款单号（幂等）
  "amount": 39.9,              // 可选，退款金额，缺省为订单实付
  "reason": "不想要了" }       // 可选，退款原因
"data": { "refundNo":"RF...", "extRefundNo":"RF-001", "orderNo":"DPH...",
  "amount":39.9, "status":"refunded", "refundedAmount":39.9, "created":true }
POST/orders/:orderNo/webhook/retry鉴权 Key + 签名

手动重发一次该订单的 order.paid 回调（仅已支付订单可触发）。

"data": { "orderNo":"DPH...", "sent": true }

六、Webhook 事件回调

主体在后台配置 callbackUrl 后，订单支付成功 / 退款成功时，平台会向其推送签名事件。推送可追溯、失败自动退避重试，也可随时通过重发接口手动补发。

事件触发时机
order.paid订单支付成功
order.refunded退款完成

回调请求体示例（JSON）：

{ "event": "order.paid",
  "orderNo": "DPH...",
  "extOrderNo": null,
  "status": "paid",
  "paidAt": "2026-09-16T08:00:00Z",
  "totalAmount": 39.9 }

七、限流与接入

项限制
读接口限流每个主体密钥 120 次 / 分钟（滑动窗口）
写接口限流每个主体密钥 30 次 / 分钟
时间戳窗口±5 分钟
nonce 防重放同一 nonce 5 分钟内不可重复
密钥生命周期可吊销/轮换/设过期/IP 白名单，由平台后台管理

接入流程：联系平台管理员开通主体，获取 keyId + keySecret → 配置回调地址 → 按本签名算法调用即可。平台不提供自助注册。
