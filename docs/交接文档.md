## 1. 项目概览

**YYeSim（SellSim）** 是一个面向全球的 eSIM 上网卡商城系统，业务链路：

> 用户（支付宝小程序授权登录）→ 浏览国家/套餐 → 下单 → 支付宝支付 → 自动对接 Tiger eSIM API 下发 eSIM → 小程序内查看激活码（LPA）/二维码安装

除 C 端商城外，还包含三块业务：

| 业务 | 说明 | 入口 |
| --- | --- | --- |
| C 端商城 | 支付宝小程序为主（同时可构建 H5/微信端） | `www.bjyyxx.com`（官网）+ 小程序 |
| 管理后台 | 订单/eSIM/套餐/主体/客服/优惠券/知识库等 | `www.bjyyxx.com/backend/` |
| 开放平台（B2B） | 授信分销模式：伙伴主体通过 API Key 或伙伴门户向平台下单卖卡，额度+钱包记账结算 | `www.bjyyxx.com/partner/`，API 前缀 `/api/open/v1` |

## 3. 本地开发环境

```bash
# 环境要求：Node 20+（推荐 22）、pnpm 11（corepack enable）
pnpm install
pnpm db:push     # 建表（需先配 DATABASE_URL 指向本地 MySQL）
pnpm db:seed     # 种子数据：36 国家 + 5 区域 + 基础套餐
pnpm dev         # 同时起 server(6660) / miniapp H5(5173) / admin(6661/backend) / web(5174)
```

本地开发注意（都是踩过的坑）：

- 本地需自备 **MySQL 8**（项目已从 SQLite 迁出，2026-09-11）。`apps/server/.env` 配 `DATABASE_URL` 指向本地 MySQL；`db.ts` 顶部已 `import 'dotenv/config'`。
- 本地 Redis 端口若被占用，在根 `.env` 设 `REDIS_PORT=6381`（容器内 server 走内部网络不受影响）。
- 拉不动 Docker 镜像时可用 1panel 加速：`docker tag docker.1panel.live/library/node:22-alpine node:22-alpine`。
- 本地起 docker compose 冒烟时，注意 mysql 服务在 `internal-mysql` profile 下。
- 小程序联调地址在 `apps/miniapp/src/utils/api.js` 的 `BASE_URL`；支付宝开发者工具需开"不校验合法域名"。
- 支付宝小程序 dev 构建缓存坏死（页面缺 axml/js 报 cannot resolve module）时：停 dev watch → 删 `dist/dev/mp-alipay` 和 `node_modules/.vite` → 重新 `pnpm dev:mp-alipay`。**不要**用 `node node_modules/.bin/uni`（Windows 下是 shell 脚本会报错）。

## 4. 生产部署架构（双机负载均衡）

| 节点 | 角色 | 部署内容 |
| --- | --- | --- |
| 主服（134.175.146.244） | 全栈 | MySQL、Redis、Qdrant、server、admin、web、partner、Caddy |
| 老服（8.138.193.6） | 出口边缘节点 | 仅 Caddy（TLS 终止 + 反代至主服）+ 单个 server 容器（`docker-compose.edge.yml`，监听 127.0.0.1:6501） |

- 老服 Caddy 通过 `CADDY_UPSTREAM` 环境变量反代所有流量到主服 Caddy:80；老服 edge 的 server 环境变量必须与主服完全一致（保证 JWT/token 互通），且 `ENABLE_WEBHOOK_RETRY=false` 防重复回调。
- 老服 edge 的 RAG 共享主服向量库：`.env` 填 `QDRANT_URL=http://<主服IP>:6333`。
- 主服 MySQL 对老服开放 1513 端口（安全组仅放行老服 IP）。
- **重要**：负载均衡期间老服 MySQL 服务不得停止，小程序需能正常访问后端。

### Compose 服务清单（docker-compose.yml）

`mysql` / `redis` / `qdrant` / `server`(内部 6660) / `admin` / `partner` / `web` / `caddy`。数据卷：`sellsim-mysql-data`、`sellsim-redis-data`、`sellsim-qdrant-data`、`caddy-data`、`caddy-config`。

### 部署方式

1. **自动**：push `master` → GitHub Actions SSH 到服务器执行部署（Secrets：`DEPLOY_HOST/DEPLOY_USER/DEPLOY_SSH_KEY/DEPLOY_PORT` + `DEPLOY_DIR` 变量）。
2. **手动**：服务器上跑 `./deploy.sh`（git pull → 依赖检查 → mysqldump 备份到 `backups/` → db push → bootstrap-sync → `docker compose build` → `docker builder prune -af`（防磁盘爆）→ up → 健康检查）。`DEPLOY_ROLE=edge` 时仅构建启动后端服务、不动 Caddy 配置。
3. **容器启动自举**：容器启动时自动执行 prisma db push 与 `bootstrap-sync.mjs`（含存量主体初始化账号等幂等逻辑）。

### 部署红线

- **deploy.sh、docker-compose*.yml、caddy-entrypoint.sh 等部署相关文件改动后必须提交 git**，否则服务器拉到旧代码（踩过：partner 容器缺失、/partner 404）。
- 伙伴门户代码（apps/partner/）同理必须入库。

## 5. 核心业务模块要点

### 5.1 eSIM 下发（Tiger eSIM 上游）

- 未配 `TIGER_CLIENT_ID/SECRET` 时为 mock 模式（生成假 LPA 激活码），配置后真实下发；状态可查 `GET /api/admin/tiger/status`。
- 后台不存储套餐数据，**实时从 TigerESIM 获取目录**（Redis 主缓存 + 内存降级 + stale-while-revalidate），"从 Tiger 刷新"会同时刷新套餐缓存与目录缓存。
- 只有后台添加并设置过价格的套餐（PackagePrice 有价行，即"白名单"）才对 C 端/开放平台可见；主套餐键为 `tigerPkgId`（数字）。
- 下发可靠性（2026-10-12 加固）：绑定成功后按退避轮询 Tiger 卡片接口取激活码（0/2/4/6/8s 共 5 次）；耗尽则精确解绑本次 Tiger 绑定并整单回滚；取卡前逐张检查 Tiger 侧残留绑定防止复卖；每 5 分钟补偿对账任务扫描"已支付超 10 分钟无 esim"订单自动补发（仅主服运行）。
- 已关联 Tiger 的套餐（含 tigerPkgId）**禁止本地改删**，需到 TigerESIM 后台操作。
- Tiger API 已知坑：激活码要调 `GET /api/card` 的 `installation` 字段兜底；`listCards` 的 `limit` 最小 5。

### 5.2 支付与退款

- 支付宝：手机网站支付/小程序支付，回调地址由 `ALIPAY_NOTIFY_HOST` 拼 `${host}/api/alipay/notify`。支付配置四要素 `ALIPAY_APP_ID/PRIVATE_KEY/PUBLIC_KEY/NOTIFY_HOST` 必须在 compose 透传。
- 订单状态流转：`pending → paid → refunded`（无取消态）；订单类型 `new/renew/change`（续费走 bindPackage 流量累加；变更先 deleteCardPackage 再 bindPackage）。
- 退款三段式：用户申请（仅待激活订单）→ 后台审批 → 执行退款；开放平台走独立 `refundOrderSelfService`。退款后优惠券自动返还。
- 测试开关：`/api/orders/:orderNo/pay` 模拟支付受 `use_real_payment` 控制。

### 5.3 优惠券（2026-10-09 上线）

- 仅作用于小程序内部订单（subjectId 为空路径），**不影响开放平台结算价 W 公式**。
- 满减券（固定 CNY）/ 折扣券（1-100%），支持指定日期/N 天/永久三种过期，含门槛、总量、每人限领。
- 核销按 CNY 计，封顶最低支付 ¥0.01；下单时事务内 `updateMany where usedCount < totalQuota` 原子核销防超发；pending 订单删除自动释放券。
- 数据表：Coupon / UserCoupon / CouponRedemption（+ Order 4 个券字段）。
- 兑换码入口在个人中心兑换。

### 5.4 开放平台 / 伙伴门户（B2B）

- 主体创建与密钥管理由平台独占，无自助注册。鉴权双模：读接口仅 `X-Api-Key`；写接口（下单/退款/重发回调/改回调地址）需 `X-Timestamp + X-Nonce + X-Sign` HMAC 签名。
- 钱包结算模型（2026-09-20）：Subject 有 `balance` + `usedQuota` + `quotaLimit`；下单优先扣余额，不足透支 usedQuota；欠款阈值 = quotaLimit，超限 409 禁下单。充值走支付宝（out_trade_no 前缀 `RC`）→ `fulfillRecharge` 先冲 usedQuota 再进 balance。
- 结算价 W 公式（占位，分成模型未最终定案）：`W = costPrice + (平台价 − costPrice) × (1 − splitPercent/100)`；未设 costPrice 则 W=平台价。
- 伙伴门户：用户名+密码登录（2026-09-24 起），含额度总览、流水、订单/eSIM、卡号池（未激活 ICCID，mono 字体一键复制）、个人中心（钱包/充值/回调地址自助配置）、`/docs` 接口文档。
- 公开 API 文档页：`/open-api`（免鉴权）。旧 `/api/external` 已 Deprecation。
- webhook 事件：`order.delivered` / `order.refunded`，入表 + 退避重试 + 手动重发。
- 主体账号相关：后台创建主体返回一次性明文账号；管理员重置密码接口 `POST /api/admin/subjects/:id/reset-password`；列表/详情接口脱敏剥离 passwordHash/salt。

### 5.5 AI 客服（客服小 Y）

- LLM 双轮：首轮带 tools（search_kb 向量检索 / get_orders / get_data_usage / get_packages / recommend_package / request_refund），服务端执行真实查库回灌；末轮 `response_format:json_object` 输出 `{reply, needHuman, category}`。注意：**首轮带 tools 时不能同时开 jsonMode**（会冲突）。
- 知识库：Qdrant 向量库（中文按句切块、余弦 top-k），连不上/未命中自动回退关键词检索；后台"知识库管理"增改删实时同步向量。嵌入模型注意 qwen 系默认 `text-embedding-v3`（1024 维）。
- 每条 AI 消息持久化 `aiRequest/aiResponse`（提示词+原始响应）并打 `[ai]` 日志。
- 转人工：仅用户明确说"转人工/人工/真人"或敏感场景（退款失败/支付纠纷/账号安全）触发；前端**没有**转人工按钮，文案统一"客服小 Y"，不出现"AI"字样。未配 API Key 自动转人工。
- 会话：状态机 `ai → human → closed`；24h 无新内容定时任务自动归档（Redis 分布式锁防多实例重复执行）；支持图片消息、全屏预览；联系方式为快照语义（会话创建时写入当时最新订单邮箱，之后不刷新）。
- WebSocket：`/ws` 路径，`ws` 库 noServer 模式 + `chatHub.ts` 单例广播；按 sessionId 订阅鉴权（admin 全部，user 仅本人）；小程序断线 3s 重连 + HTTP 增量兜底 + 消息 id 双保险去重。
- **WS 认证历史坑**：`ws` noServer 模式下 `socket.url` 是 undefined，token 必须从 `connection (rawSocket, req)` 回调的 `req.url` 取（已修复，commit 8e9100c，勿回退）。

### 5.6 邮件下发

- 支付成功邮件：统一布局 `buildHtml`/`buildPlain` 双版本（text/plain + text/html 内容一致），附件 PDF（pdf-lib + simhei.ttf）含套餐信息、LPA 激活码、二维码、安装说明。
- Logo 经 CID 内嵌，路径 `apps/server/assets/logo.png`（缺失回退品牌字标）。
- 反垃圾合规（踩过坑）：不用 emoji/营销渐变色/夸张主题；事务性主题格式；含 List-Unsubscribe、Reply-To（support@bjyyxx.com）、CAN-SPAM 页脚（官网 www.bjyyxx.com + 发件方 + 邮寄地址）。

## 9. 已知坑与红线（接手必读）

1. **不要物理删除有 eSIM 关联的 Order 行**（2026-10-12 生产事故）：`Esim.order` 是必关联（FK Restrict），多处 `include:{order:true}` 读取时 Prisma 抛 "Inconsistent query result" 未捕获 → 容器崩溃循环 → Caddy 502。处理方式是整单转移归属（Order.user_id 与 Esim.user_id 一起改）；如必须物理删除，先把 Esim.orderId 改 optional 再发版。
2. **schema.prisma 注释必须纯 ASCII**：含中文注释会导致 `prisma generate` 报 Invalid character（Linux Docker 也复现，且 `prisma validate` 却能过，极具迷惑性）。提交前做非 ASCII 字节检查。
3. **Prisma `$queryRaw ... FOR UPDATE` 返回 MySQL snake_case 列名**：不会映射回 camelCase。quota.ts 已显式别名（`quota_limit AS quotaLimit`）；新写 raw SQL 必须加别名，否则静默 NaN、欠款阈值判断失效。
4. **本地测试起容器**：Redis 用 `REDIS_PORT=6381`；镜像拉取用 1panel 加速 tag。
5. **Docker 挂载**：只挂 `prisma/data`，**不要挂整个 prisma 目录**（会覆盖 schema.prisma 导致 engine 报错）。
6. **老服 edge 环境变量必须与主服一致**（token 互通），并保持 `ENABLE_WEBHOOK_RETRY=false`。
7. **部署相关文件（deploy.sh/compose/caddy-entrypoint.sh/apps/partner）改完必须提交**，否则线上拉旧代码。
8. **所有订单/eSIM 接口必须鉴权并按 userId 过滤**（历史上出过越权问题）。
9. 优惠券并发核销依赖 `updateMany` 条件更新，改动核销逻辑时保持原子性。
10. 小程序消息列表改动注意"本地乐观 id（local_ 前缀）+ 增量 afterId + 去重"三者的耦合关系，动一处要三处一起看。
11. 汇率/多货币：存储货币与展示货币解耦（PackagePrice.currency + Setting 汇率），换算纯函数在 `priceOverride.ts`。
12. AI 工具循环：首轮 tools 与 jsonMode 互斥；qwen 系模型第二轮可能输出散文，`needHuman` 只看 `parsed.need_human===true`（已修，勿回退成 `!reply` 判断）。
